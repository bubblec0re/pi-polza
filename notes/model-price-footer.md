# Цена текущей модели в футере

Заметка фиксирует доказательства и решения для строки `(X in / Y out ₽/1M)` в футере Polza.

## Что показываем

`Polza <баланс> ₽ | Spent <расход> ₽ | (11.74 in / 58.72 out ₽/1M)`

* Числа — **цены каталога Polza** в нативных рублях за 1 млн токенов (input / output). Это та же цифра,
  которую пользователь видит на сайте Polza и в `/polza-model-info`; она нужна, чтобы решить, менять ли модель.
* `Spent` по-прежнему считается только по `usage.cost_rub` и остаётся авторитетным фактом списания.
  Цена каталога в бухгалтерию не попадает (см. `instructions/project-rules.md` §2).
* Неизвестная цена (модель вне каталога, медиа-модель) — сегмент **не рисуется**. Не `0.00`.
* Кэш-цены (`input_cache_read_per_million`) в футер не выводятся — для этого есть `/polza-model-info`.

## Источники данных

| Источник | Когда | Стоимость |
| --- | --- | --- |
| `ResolvedModel.pricing.polzaRUB` (реестр) | при старте Pi каталог запрашивается заново; `/polza-refresh` | 0 запросов в рантайме |
| `GET /api/v1/models/{id}` | если цены нет или она старше TTL (1 час), и при смене модели | 1 запрос на модель в час |

`GET /api/v1/models/{id}` — публичный endpoint (ключ не требуется), проверено `npm run probe:price`:

```text
anthropic/claude-haiku-5.5
  models/{id}: 152 ms, 21485 B, provider "google-vertex/global"
  pricing: in 11.743400 / out 58.717000 / cache-read 1.174340 RUB per 1M
  catalog:    1239 ms, 35315 B, 22 hits — pricing identical
  providers:  10 routes, prompt ₽/1M from 11.743400 to 12.917740
```

* Одиночный endpoint отдаёт **те же** цены, что и пагинированный каталог (проверено на 5 моделях).
* Неизвестный id: `HTTP 404`, `{"error":{"code":"NOT_FOUND"}}` → цена остаётся неизвестной.
* Размеры: 5.5 КБ — 82 КБ, 67–319 мс; плюс 1 запрос на моделях, где нужен `providers[]`.
* Цены — десятичные **строки**, `currency: "RUB"`, 8 знаков после запятой. Никакой конвертации валют.

## Почему TTL = 1 час

Цены дрейфуют медленно (RUB-значения выглядят как результат пересчёта по курсу): `aion-labs/aion-2.0`
94.1360 → 93.9472 ₽/1M за 4 недели (−0.2 %). Опрос раз в час — с большим запасом; таймеров и поллинга нет:
запрос идёт только при активации футера/смене модели, если значение отсутствует или устарело.

## Выравнивание вправо

`ctx.ui.setStatus` не умеет выравнивание. Pi сам выравнивает имя модели вправо обычными пробелами внутри
своего `render(width)` (`dist/modes/interactive/components/footer.js`):

```js
const padding = " ".repeat(width - statsLeftWidth - rightSideWidth);
statsLine = statsLeft + padding + rightSide;
```

Статусы расширений добавляются отдельной строкой и только обрезаются: `sortedStatuses.join(" ")` +
`truncateToWidth(...)`. Поэтому используется тот же приём со стороны расширения:

* ширина — как у pi-tui: `process.stdout.columns || Number(process.env.COLUMNS) || 80`
  (`pi-tui/dist/terminal.js`);
* измерение — `visibleWidth()` из `@earendil-works/pi-tui` (тот же помощник, что у Pi);
* `pad = columns - 1 - visibleWidth(text)` (один запасной столбец, чтобы строка не переносилась);
* на `process.stdout.on("resize")` (событие, которое слушает и pi-tui) строка перерисовывается.

Ограничения: паддинг попадает в текст при выделении футера, а при появлении чужого статуса (`pi-firecrawl`
показывает его только на время вызова инструмента) строка переполняется и обрезается справа — цена временно
исчезает и возвращается на следующей перерисовке. Переключатель `STATUS_ALIGNMENT = "right" | "left"` в
`index.ts` возвращает прежнее поведение одной строкой.

## Формат и точность

Выбран `(11.74 in / 58.72 out ₽/1M)`: подсказки `in`/`out` остаются, `₽/1M` печатается один раз
(27 символов против 29 у варианта `(11.74₽/1M in, 58.72₽/1M out)`).

Точность адаптивная, потому что разброс цен огромен (пробник, 412 моделей): input ₽/1M от 0.46 до 17 615,
output до 70 460. Фиксированные два знака превратили бы дешёвые модели в `0.00`.

| Диапазон | Формат | Пример |
| --- | --- | --- |
| ≥ 1000 | целое | `17615` |
| ≥ 1 | 2 знака | `11.74`, `587.17` |
| ≥ 0.1 | 3 знака | `0.460` |
| < 0.1 | 4 знака | `0.0871` |

## Проверка

```bash
npm run probe:price          # живая проверка endpoint + таблица величин
npm test                     # formatPricePerMillion, цена в футере, TTL, выравнивание
npx tsc --noEmit             # типы (в чистом checkout нужны peer-пакеты Pi; сами изменённые
                             # файлы проверяются чисто)
```

Ручная проверка в Pi: переключение моделей `/model`, `/polza-refresh`, ширина окна 60/80/120, ресайз,
отключённая сеть (цена остаётся последней известной), не-Polza провайдер (строки нет).
